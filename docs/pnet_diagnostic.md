# Диагностика PNET Warning 26007903

## Наблюдения по имеющимся файлам

В загруженном ранее полном `report(1).json` предупреждение возникает на этапе
`run` обоих сценариев. На этапе `restart` список предупреждений пуст.
В новом `agent_routerai_run_check.json` снова есть предупреждения на этапе `run`,
а давления совпадают с прежними значениями.

По полному отчёту вычислено:

| Величина | base / run | plus10 / run |
| --- | ---: | ---: |
| Давление входа, bara | 11.9029857625 | 11.9020199666 |
| Давление выхода, bara | 10.0001560775 | 10.0001560875 |
| Перепад, Па | 190282.968494 | 190186.387912 |
| 200 × abs(Pвх − Pвых) / (Pвх + Pвых), % | 17.37494738 | 17.36689427 |
| Процент из предупреждения, % | 17.37495 | 17.36689 |
| Перепад минус сумма трёх компонентов, Па | −0.00019301 | −0.00013666 |

Давления в формуле абсолютные. Проценты совпадают до точности отображения
предупреждения. Это численное наблюдение; определение внутренней переменной
`branch error` и причина её появления пока не установлены.
Число 17.37% нельзя автоматически приравнивать к погрешности промыслового
прогноза или к нарушению баланса жидкости на 17.37%.

Сумма компонентов перепада рассчитана из
`CumulativeFrictionPressureDifference`, `CumulativeElevationPressureDifference`
и `CumulativeAccelerationPressureDifference`. Их согласование с общим
перепадом не доказывает корректность модели флюида, корреляции или геометрии.
Отсутствие предупреждения при Restart также не доказывает устранение причины.

Уменьшение давления входа при +10% расхода в этом отчёте арифметически
складывается из изменения компонентов: трение увеличилось примерно на
210.38 Па, высотная составляющая уменьшилась на 306.96 Па;
общий перепад уменьшился примерно на 96.58 Па.
Физическое обоснование такого поведения требует отдельной проверки.

В старом ручном `.tnt` есть `setup tol=0.01 maxiter=100` и алгоритм Wegstein.
Эти сведения относятся именно к старому ручному файлу; настройки нового
автоматического расчёта нужно подтвердить по его собственным `.tnt`.

## Собрать данные нового расчёта

Распакуйте `well_agent_pnet_diagnostic.zip` в корень локального репозитория.
В обычном cmd из корня выполните:

```bat
.venv-mcp\Scripts\python.exe scripts\check_pnet_warning.py ^
  --registry "C:\Users\User\Desktop\well-agent-data\mcp_registry" ^
  --run-id f795f8c9-881d-579f-98b4-247f3de39807 ^
  --output "C:\Users\User\Desktop\well-agent-data\pnet_diagnostics_01.zip"
```

Выберите новое имя ZIP, если оно уже существует. Выходной ZIP должен находиться
вне реестра и папки самого расчёта. Сборщик читает зарегистрированный отчёт
после штатной проверки хешей и записывает только новый архив.
Он работает в `.venv-mcp`, не вызывает API, не требует запуска Toolkit
и не запускает PIPESIM. Повторная настройка configure-runner не требуется.

В ZIP попадут:

- `diagnostic.json`: давления, компоненты, сопоставление процентов,
  фазовые балансы и различия Run/Restart;
- оригинальный `report.json` этого запуска;
- имеющиеся `results.json` и `engine_console.txt` четырёх этапов;
- входные `.tnt` из папок `base/engine_input` и `plus10/engine_input`;
- существующие `sdk.log` и стандартные текстовые файлы вывода движка.

Для каждого собранного файла фиксируется SHA-256. Отсутствующие результаты
помечаются как отсутствующие; числа не заменяются нулями. Настоящие `.pips`,
`.env`, двоичные временные файлы и весь реестр в пакет не включаются.
В текстовых файлах могут сохраняться локальные пути и исходные данные модели.

Пришлите полученный `pnet_diagnostics_01.zip` и вывод cmd. Полные сообщения
движка нужны, чтобы сопоставить предупреждение с этапами решения и проверить,
относится ли оно к промежуточному состоянию или к окончательному результату.
Если этих сообщений недостаточно, следующим шагом будет проверка документации
установленного PIPESIM или отдельный диагностический запуск в копии модели.
До этого причина отмечается как `CAUSE_NOT_ESTABLISHED`.

исключение посторонних файлов, блокировку перезаписи и изменённых регистраций.
