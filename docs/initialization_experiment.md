# Подготовка эксперимента с начальными приближениями

Цель эксперимента: выяснить, зависит ли предупреждение PNET 26007903 от
начального приближения давления при неизменных физических входных данных.

## Почему сначала нужно уточнить API

В имеющемся описании Toolkit 2021.1 у `networksimulation` нет подтверждённого
публичного метода задания начальных приближений. Метод `set_conditions`
задаёт граничные условия. У `networkoptimizersimulation` есть методы с именем
`get_initial_conditions`, но это другая задача. Переносить их автоматически
на обычный сетевой расчёт нельзя.

`Parameters.Source.PRESSURE` также нельзя использовать наугад: изменение
давления как граничного условия нарушит чистоту эксперимента.

## Выполнить проверку установленной версии

Распакуйте пакет в корень репозитория. Из этого корня в обычном cmd:

```bat
.venv-mcp\Scripts\python.exe scripts\inspect_network_initialization.py ^
  --registry "C:\Users\User\Desktop\well-agent-data\mcp_registry" ^
  --output "C:\Users\User\Desktop\well-agent-data\network_initialization_api.json"
```

Скрипт читает путь установленного Toolkit из `runner.json`, ищет связанные
с приближениями методы и описание в его исходниках и локальной документации.
Он не импортирует Toolkit, не открывает модель, не занимает лицензию,
не вызывает API и не запускает расчёт. Существующий JSON не перезаписывается.

В отчёте будут имена публичных методов классов модели и сетевого расчёта,
фрагменты документации/исходников вокруг найденных терминов и контрольные
суммы этих исходников. Это материалы для выбора поддерживаемого способа,
а не подтверждение, что каждый найденный метод подходит для эксперимента.
В отчёте могут присутствовать локальный путь установки и фрагменты кода SLB.

Пришлите вывод cmd и `network_initialization_api.json`.

## Как будет устроен сам эксперимент

После подтверждения способа задания приближений:

1. Для каждого варианта создаётся новая отдельная копия подготовленной модели.
2. Сохраняются одинаковые расходы, температура, давление выхода, геометрия,
   флюид, корреляции и параметры сходимости.
3. Меняется только подтверждённое начальное приближение давления входа:
   штатное, близкое к найденному решению и отклонённое от него.
4. Каждый вариант начинает обычный Run без подстановки решения другого варианта.
5. Сопоставляются текст предупреждения, число итераций, RMS, конечные давления
   и фазовые балансы. Изменения физических условий считаются ошибкой эксперимента.

Если поддерживаемого API нет, нужен документированный способ через интерфейс
PIPESIM или engine keywords. Недокументированные параметры подбирать не будем.
Рабочая модель, MCP-профиль и результаты прежних запусков остаются исходной базой.
