# Подготовка сети АГЗУ-6 через MCP

Команда `agent.py prepare-model` открывает локальную сессию MCP с инструментами `prepare_model` и `apply_approved_changes`. Путь к комплекту данных задаёт оператор. Клиент `agent.py ask` продолжает работать с зарегистрированными расчётами. Сборка использует существующий `scripts/build_network_model.py` и установленный PIPESIM Python Toolkit 2021.1.

Из корня репозитория в CMD задайте путь к Python окружения MCP. Для стенда команды подходит команда

```bat
set "MCP_PY=%USERPROFILE%\Downloads\well-agent-Troshin-Bogdanov-Sokolov-main\well-agent-Troshin-Bogdanov-Sokolov-main\.venv-mcp\Scripts\python.exe"
```

### Проверка плана

```bat
"%MCP_PY%" agent.py prepare-model --data "%USERPROFILE%\Desktop\well-agent-data" --plan-only
```

Проверьте в выводе `PLAN_READY` имена источника, линии и стока, 53 точки профиля, диаметр и стенку в мм, давление на выходе в барах абсолютных, температуру в °C и оба расхода в м³/сут при условиях stock tank. Сверьте их с манифестом. Программа читает исходную модель с флюидом `models/t1_fluid_auto.pips`, её JSON, геометрию с профилем и `fluid/scenario_rates.json`. План содержит хеши исходников и скриптов. Отчёт каждого обращения хранится в `mcp_registry/traces`.

### Решение оператора

```bat
"%MCP_PY%" agent.py prepare-model --data "%USERPROFILE%\Desktop\well-agent-data"
```

При другом расположении Toolkit добавьте к команде `--toolkit-root "полный путь к PIPESIM_PTK_2021.1"`. Пустой ответ на запрос подтверждения сохраняет решение `DECLINED` в журнале. Для сборки введите `ДА` после просмотра плана. Утверждение относится к показанному `plan_id`. Сервер сверяет хеши и сохраняет снимок входов вместе с решением оператора в `mcp_registry/model_builds/<plan_id>/attempt-1/`. Полный SHA-256 оригинального манифеста относится к сохранённому `inputs/manifest.json`. В рабочем `inputs/pipe.json` путь к профилю указывает на локальную копию CSV. Путь реестра при необходимости можно сократить, переместив комплект в более короткий каталог с сохранением ссылок на геометрию.

При успехе ответ `VERIFIED` содержит пути к новой модели `network.pips` и отчёту `network.json`, хеш готовой модели и статус `after_reopen`. Раздел `after_reopen` полного отчёта содержит параметры, связи, геометрию, условия обоих режимов и их сверку после сохранения и открытия. Исходная модель с флюидом остаётся в своём каталоге. Готовность изотермического режима и гидравлический расчёт относятся к следующей операции.

Повтор с тем же планом и подтверждением возвращает `ALREADY_BUILT`, если модель и отчёт совпадают. Для завершившейся неудачной попытки смотрите `worker.log` и отчёт, если он создан. При повторном подтверждении после завершившегося сбоя создаётся отдельная попытка. При `PENDING` повтор проверяет результат прежней попытки. Если процесс прекратился без записи кода выхода, сохраните папку для диагностики и проверьте процесс на стенде до дальнейших действий.
