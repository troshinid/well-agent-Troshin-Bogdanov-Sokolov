# § 3.6. Входные данные таблицы АГЗУ

Проверялся пользовательский интерфейс импорта `scripts/check_agzu.py` на базе `58ae83d`. Четыре синтетических файла независимо подаются этому скрипту через командную строку. Каждый тест использует новую временную папку. До изменений два теста из четырёх выявили расхождения с ожидаемым поведением.

| Случай | Вход и ожидаемый результат | Факт на исходной версии | Факт после исправления |
|---|---|---|---|
| Неверная единица | В C20 явно указано «Обводненность, %», C21 содержит 0,6. Требуется уточнить шкалу до пересчёта. | Импорт завершился с кодом 0. Программа прочла 0,6 как долю и посчитала 60%. | Код 2, сообщение указывает Sheet1!C20 и предлагает уточнить единицу. Файл отчёта не создан. |
| Выход за диапазон | В C21 записана доля 1,2. Ожидается отказ с адресом ячейки. | Код 2, сообщение «C21: обводнённость должна быть долей от 0 до 1». | Тот же отказ, отчёт не создан. Реализация этой проверки уже была в main. |
| Неразобранный документ | Файл с расширением .xlsx содержит обычный текст. Ожидается отказ с именем файла и причиной. | Код 1 и traceback BadZipFile. Численный отчёт не создан. | Код 2, сообщение «Не удалось прочитать книгу agzu.xlsx: повреждён или неверен формат XLSX». Отчёт не создан. |
| Корректный контроль | Обычный заголовок из исходного шаблона, 0,6 с форматом отображения Excel 0%. | Импорт успешен. | Код 0, в строке скважины сохранена доля 0,6. |

Исправление проверяет заголовок обводнённости в каждом из четырёх блоков известного шаблона АГЗУ. Формат отображения ячейки сам по себе не меняет значение Excel. На исходной книге команды проверены 13 строк и те же контрольные суммы дебитов: жидкость 989,6, вода 145,9601, газ 17 020 в исходной шкале.

## Как повторить

Из корня репозитория с установленным Python среды проекта выполните:

```bat
python -m pip install -r requirements.txt
python -m unittest discover -s tests -p test_agzu_inputs.py -v
```

Для полного набора нужны также зависимости из `requirements-agent.txt`. В проверенном окружении прошли 88 тестов, включая 4 новых. Доказательства относятся к импорту XLSX до вызова ПО. Проверка не охватывает распознавание PDF/сканов или ввод единиц в произвольном текстовом запросе. Закрытие остальных случаев § 3.6 требует отдельной матрицы.
