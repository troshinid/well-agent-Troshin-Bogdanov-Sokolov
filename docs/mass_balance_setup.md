# Массовый баланс: установка и проверка

Распакуйте `well_agent_mass_balance.zip` в корень локального репозитория
с заменой файлов. Новых зависимостей нет, используется прежняя `.venv-mcp`.
`.env`, модели и реестр в пакет не включены.

## Что добавлено

Адаптер запрашивает `ProfileVariables.MASS_FLOWRATE` (`MassFlowrate`).
Фактическое расположение подтверждено ответом Toolkit 2021.1:
`profile.<branch>.MassFlowrate`, единица в `profile_units.MassFlowrate`.
Вход берётся из первой точки ветви `agzu6_out`, выход — из последней точки
ветви `tiein_agzu4_agzu1`. Проверяются непустые согласованные колонки.
Оба конца одной трубы не подменяют две границы сети.

Первоначальное чтение `node.MassFlowrateFluid` оказалось неверным: имя есть
в definitions, но в фактическом узловом ответе этой модели его нет.
Исправление и команда повторного запуска: [mass_balance_fix.md](mass_balance_fix.md).

Массовые расходы явно переводятся в кг/с по единице ответа API.
Масса из объёмных расходов или предполагаемой плотности не вычисляется.
Для проверенной цепочки без промежуточных отборов:

- знаковая невязка: `m_in − m_out`, кг/с;
- невязка по модулю: `abs(m_in − m_out)`, кг/с;
- относительная: `100 × abs(m_in − m_out) / m_in`, % при `m_in > 0`.

Расходы трактуются как положительные величины по направлению проверенной
сети. Отрицательное значение требует отдельного контракта обратного потока;
оно не заменяется модулем. Пропуск, неконечное число или неизвестная единица
дают `CHECK_REQUIRED` и `null` вместо отсутствующей величины.
Одна только недоступность массовых данных даёт `numerical_validation=NOT_ASSESSED`,
а не `OUT_OF_TOLERANCE`. Исходная ошибка сохраняется в `mass_balance_error`.

## Допуски и статусы

Файл `config/mass_balance.json` по умолчанию содержит:

```json
{
  "absolute_tolerance_kg_s": null,
  "relative_tolerance": null,
  "approval_reference": null
}
```

При таком файле невязка вычисляется, но оценка массового баланса остаётся
`NOT_ASSESSED` / `NO_APPROVED_TOLERANCE`. Это ожидаемо до утверждения допуска.
Допуск сетевого решателя `setup tol` сюда не переносится.

После утверждения абсолютный допуск задаётся в кг/с, относительный — в долях,
а не процентах. Для любого заданного порога обязателен `approval_reference`:
источник/идентификатор согласования. Код проверяет наличие ссылки;
действительность согласования подтверждает ответственный человек.

Критерий до округления:
`abs(m_in − m_out) <= max(abs_tol, rel_tol × m_in)`.
Незаданный порог не участвует в max. При нулевом входном расходе относительная
невязка не определена (`null`), для оценки нужен абсолютный допуск.
Превышение утверждённого допуска блокирует успешный статус адаптера.

Массовый баланс имеет отдельный статус. При незаданном допуске существующие
проверки воспроизведения могут быть `OK`, а массовый баланс — `NOT_ASSESSED`.
`physical_validation` по-прежнему остаётся `NOT_ASSESSED`.

## 1. Обновить профиль запуска

Изменились worker и файлы проверки: нужно штатно обновить их контрольные суммы.
После завершения прежних расчётов выполните из корня репозитория:

```bat
.venv-mcp\Scripts\python.exe -m src.well_agent_mcp configure-runner ^
  --registry "C:\Users\User\Desktop\well-agent-data\mcp_registry" ^
  --seed-run-id a6c13b93-011d-5a07-8107-3cfb628eb843 ^
  --prepared-model "C:\Users\User\Desktop\well-agent-data\runs\agzu6_isothermal_auto_2\isothermal_auto.pips" ^
  --toolkit-root "C:\Program Files\Schlumberger\PIPESIM_PTK_2021.1" ^
  --output-root "C:\Users\User\Desktop\well-agent-data\mcp_runs"
```

Ожидается `Runner: CONFIGURED`. Команда сохраняет профиль, расчёт не запускает.
После изменения файла критериев профиль также обновляется этой командой.

## 2. Выполнить новый расчёт через агента

Используйте новый request-id: команда ниже создаст его автоматически.
Прежний UUID `887ccd52-dc39-4ce3-ae4b-c7c144c2706e` после изменения профиля
не переиспользуется. Старые результаты доступны для отдельного чтения.

```bat
.venv-mcp\Scripts\python.exe agent.py ask ^
  --registry "C:\Users\User\Desktop\well-agent-data\mcp_registry" ^
  --run-id a6c13b93-011d-5a07-8107-3cfb628eb843 ^
  --allow-run ^
  --request "Выполни новый расчёт согласованных base и plus10 для участка АГЗУ-6 и сравни результаты" ^
  --output "C:\Users\User\Desktop\well-agent-data\agent_mass_balance_check.json"
```

Здесь выполняется настоящий новый расчёт PIPESIM и запрос RouterAI.
На время запуска завершите другие расчёты PIPESIM.
Если output уже существует, выберите новое имя.

Для обоих сценариев ожидаются входной/выходной массовые расходы в кг/с,
невязки и `оценка массового баланса: NOT_ASSESSED` с пояснением об отсутствии
допуска. Маленькая невязка сама по себе не даёт `OK`.

Пришлите вывод и `agent_mass_balance_check.json`. При ошибке экспорта также
нужен новый `calculation/report.json`, поле `mass_balance_error`.
Проверки хешей не обходите, старые зарегистрированные отчёты не редактируйте.

## Формат и проверка

Новые полные отчёты объявляют `result_features: ["total_mass_balance_v1"]`.
В каждом Run/Restart есть `mass_balance` и проверка `mass_flow_available`;
при чтении сохраняется исходная единица, а при наличии допуска добавляется
`mass_balance_within_tolerance`. Критерии и SHA-256 конфигурации фиксируются
в отчёте, config и модуль расчёта включены в профиль запуска.

MCP независимо пересчитывает невязки и оценку на обоих этапах запрошенного
сценария. Несогласованные величины, узлы, единицы, критерии или статусы
отвергаются. Агент показывает выбранный этап (обычно Restart), оба этапа
остаются в полном отчёте. Предупреждения PNET сохраняются.

Прежние отчёты читаются с `mass_balance.assessment=NOT_ASSESSED`,
`reason=NOT_EXPORTED` и пустыми величинами. Новый worker не может подменить
обещанный экспорт старым форматом.

Пройдены 79 автоматических тестов, включая проверки единиц, нулевого расхода,
граничного допуска, подмены значений и настоящего MCP stdio с имитацией worker.
Исправленное чтение проверено повторной обработкой реального сохранённого
ответа `base/run`. Полный новый цикл обоих сценариев ещё нужно выполнить.

```bat
.venv-mcp\Scripts\python.exe -m unittest discover -s tests -p "test_*.py" -v
```
