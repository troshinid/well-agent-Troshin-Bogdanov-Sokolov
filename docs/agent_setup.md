# Текстовый агент: RouterAI → MCP → PIPESIM

Экспорт массовых расходов и обновление профиля при установке новой версии:
[mass_balance_setup.md](mass_balance_setup.md).

## Область первой версии

Агент понимает запрос через LLM и выполняет одну из операций:

- читает зарегистрированный расчёт: base, plus10 или сравнение;
- по явному запросу повторяет согласованную пару base/plus10 в новой копии
  подготовленной модели, если запуск разрешён локальным флагом `--allow-run`;
- отказывает при неоднозначности, неподдерживаемой задаче или запросе изменения модели.

LLM не получает инструмент запуска команд, пути к файлам, API-ключ или лицензионные
переменные. В RouterAI передаются текст пользовательского запроса, инструкция
с границами задачи и JSON-схема. Модель возвращает только action/scenario/reason.
UUID и аргументы MCP добавляет локальный код. Исходные документы и расчётные
результаты в RouterAI эта версия не отправляет. Текст запроса не должен
содержать закрытых данных или секретов.

Числа, единицы, предупреждения и статусы в ответе берутся из MCP; разницу давления
вычисляет проверяемый код. Ответ собирается по шаблону. Свободное инженерное
заключение LLM и создание/изменение модели пока не реализованы.

## 1. Установка в существующее окружение

Нужен Python 3.11+; у команды уже создано `.venv-mcp` на Python 3.13.
Все команды выполняются из корня репозитория, в обычном cmd.
Не устанавливайте эти зависимости в Python 3.8 из PIPESIM Toolkit.

```bat
.venv-mcp\Scripts\python.exe -m pip install -r requirements-agent.txt
```

Код MCP этой поставкой не меняется. В scripts/check_geometry.py восстановлено
начало файла, обрезанное в GitHub. Восстановленная версия побайтово совпадает с
версией из успешного agzu6_network_4.json команды (SHA-256
e050e3daf6942218203a9b204cada860de9a1e6a835160b5db66abf5a365fc56).
Если у вас осталась та же рабочая локальная копия, повторная регистрация модели
и configure-runner не нужны. В другой копии при INPUT_MISMATCH не обходите
проверку хешей: сначала сверяйте версии файлов и локальный профиль.

## 2. Локальная настройка RouterAI

Нужен действующий API-ключ RouterAI. Адрес API задан в коде:
`https://routerai.ru/api/v1`, запросы идут на `/chat/completions`.
Модель по умолчанию — `deepseek/deepseek-v4.1-flash-1017`.
На странице RouterAI для неё заявлены structured outputs и response_format.
Код передаёт `response_format.type=json_schema`, `strict=true` и дополнительно
проверяет ответ локально. Параметр OpenRouter `provider.require_parameters`
не отправляется. Автоматической замены модели, ослабления схемы и повторов нет.

```bat
.venv-mcp\Scripts\python.exe agent.py configure-llm
```

Программа попросит ключ (ввод скрыт) и ID модели (Enter оставляет модель по умолчанию),
затем создаст новый `.env` в
корне проекта. Сообщение CONFIGURED означает только сохранение настроек,
а не проверку API. Не передавайте ключ через аргументы командной строки.
Если `.env` уже существует, откройте его локально в редакторе и задайте:

```dotenv
ROUTERAI_API_KEY=ваш_секретный_ключ
ROUTERAI_MODEL=deepseek/deepseek-v4.1-flash-1017
```

При переходе с OpenRouter замените в `.env` строки `OPENROUTER_API_KEY` и
`OPENROUTER_MODEL` строками выше. Старый ключ не переносите: нужен новый ключ RouterAI.
Старые переменные `OPENROUTER_*` код больше не читает.
`ROUTERAI_MODEL` можно не задавать: используется модель по умолчанию; пустое
значение считается ошибкой настройки. Существующие переменные окружения
`ROUTERAI_*` имеют приоритет над `.env`.
Файл `.env` исключён через `.gitignore`, но при загрузке через GitHub в браузере
нужно самостоятельно убедиться, что выбраны только файлы кода и `.env.example`.
Никогда не публикуйте `.env`, реальные модели, реестр, worker.log или отчёты.

RouterAI-вызов может расходовать средства по тарифу выбранной модели.
Один новый запрос агента делает один LLM-вызов; автоматических повторов API нет.
Сохранённый план при повторе того же request_id не требует нового LLM-вызова.

## 3. Первый запуск: прочитать уже проверенные результаты

У команды последний проверенный расчёт зарегистрирован как
`040c309a-ab7b-55b3-ab0c-6bf9731e230a`. В другой копии реестра используйте UUID
из собственного успешного mcp_run_check_2.json, а не этот пример.

```bat
.venv-mcp\Scripts\python.exe agent.py ask ^
  --registry "C:\Users\User\Desktop\well-agent-data\mcp_registry" ^
  --run-id 040c309a-ab7b-55b3-ab0c-6bf9731e230a ^
  --request "Сравни сохранённые результаты base и plus10 для участка АГЗУ-6" ^
  --output "C:\Users\User\Desktop\well-agent-data\agent_read_check.json"
```

Новый PIPESIM-процесс не должен запускаться. Ожидаются Agent: SUCCESS,
численные проверки OK и физическая проверка NOT_ASSESSED. В JSON должны быть
task.action=read_results и evidence с вызовом read_results. Предупреждения
исходного Run сохраняются, даже если Restart их не повторяет.

Сохраните вывод и JSON. Для проверки присылайте agent_read_check.json;
`.env` не нужен. Ошибка API, схемы или MCP не заменяется заранее известными числами.

## 4. После успешного чтения: новый расчёт по текстовому запросу

Должен существовать прежний профиль configure-runner. Для пересчёта передайте
именно его исходный seed_run_id, а не UUID последнего созданного расчёта.
У команды это `a6c13b93-011d-5a07-8107-3cfb628eb843`.
Не запускайте параллельно ручной PIPESIM или другие расчёты, занимающие лицензию.

```bat
.venv-mcp\Scripts\python.exe agent.py ask ^
  --registry "C:\Users\User\Desktop\well-agent-data\mcp_registry" ^
  --run-id a6c13b93-011d-5a07-8107-3cfb628eb843 ^
  --allow-run ^
  --request "Выполни новый расчёт согласованных base и plus10 для участка АГЗУ-6 и сравни результаты" ^
  --output "C:\Users\User\Desktop\well-agent-data\agent_run_check.json"
```

Ожидаются task.action=run_steady_state, затем два вызова в evidence:
run_steady_state и read_results нового run_id. Конфигурация и настройки модели
берутся из проверенного локального профиля; LLM их не задаёт.
Успех этой проверки подтверждает реальную цепочку RouterAI → агент → MCP →
PIPESIM. Успех чтения из п. 3 подтверждает только цепочку до чтения отчёта.

## 5. Повтор и незавершённый запуск

request_id печатается и сохраняется в --output до сетевых вызовов. План и журнал
сохраняются в registry/agent_requests и registry/agent_traces; журнал ссылается
на MCP trace_id в evidence. Исходные документы остаются неизменными.

Для повтора используйте тот же текст, --registry, --run-id, --allow-run и
--request-id из предыдущего вывода/JSON. Для --output укажите новое имя файла.
После перехода на RouterAI для новых обращений используйте новый request_id
(по умолчанию он создаётся автоматически). Если остался незавершённый расчёт
старой версии, сначала выясните его исход через MCP с прежним request_id.
Не меняйте модель RouterAI или версию инструкции между повторами:
при несовпадении контекста будет REQUEST_CONFLICT.

При таймауте или обрыве после отправки расчёта его исход может быть неизвестен.
Не создавайте новый request_id: повтор прежнего позволяет MCP проверить квитанцию
и вернуть уже созданный результат. Автоматического убийства процесса или
второго запуска нет. Повтор завершившегося неуспешного задания возвращает тот
же отказ; для нового запуска после исправления причины нужен новый запрос.

## 6. Проверки и ограничения

```bat
.venv-mcp\Scripts\python.exe -m unittest discover -s tests -p "test_*.py" -v
```

Проверки агента используют имитацию HTTP RouterAI и worker; один тест читает
синтетический отчёт через настоящий MCP stdio. Они проверяют маршрутизацию,
границы аргументов, отказы, частичные данные, журнал и повтор. Они не проверяют
качество реальной LLM, устойчивость её классификации к всем prompt injection,
лицензию Windows или точность физической модели.

Для приёмки отдельно нужны реальные запросы к выбранной модели: успешное чтение,
новый расчёт, отказ на изменение параметров, неоднозначный запрос и попытку
подменить инструкции. Сохраняйте фактические ответы, включая неверную классификацию,
если она возникнет. Это часть последующего проверочного набора, а не выполненные тесты.

Соответствие промысловым замерам остаётся NOT_ASSESSED. Начальные предупреждения
PNET не скрываются; их отсутствие при Restart не доказывает устранение причины.
