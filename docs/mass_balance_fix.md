# Исправление чтения массовых расходов Toolkit 2021.1

В предоставленном `mass_export_diagnostics_01.zip` есть точная причина сбоя:
`mass_balance_error = KeyError: 'MassFlowrateFluid'`.
Узловая переменная отсутствует, но реальные массы уже экспортированы в
`profile.agzu6_out.MassFlowrate` и `profile.tiein_agzu4_agzu1.MassFlowrate`.
В `profile_units.MassFlowrate` явно указано `kg/s`.

Теперь читаются первая точка входной ветви и последняя точка выходной ветви.
Наличие обеих ветвей, непустые массивы, конечность значений, согласованная
длина с колонками Pressure/TotalDistance и единица проверяются.
Масса на обоих концах одной трубы не подставляется вместо входа и выхода сети.
В нормализованном ответе `source_variable` показывает `MassFlowrate`.
Старый формат с `MassFlowrateFluid` оставлен для чтения прежних записей.

Повторная обработка сохранённого реального ответа `base/run` дала:

| Показатель | Значение |
| --- | ---: |
| Вход, кг/с | 0.6546964194270672 |
| Выход, кг/с | 0.6546964218342646 |
| Вход минус выход, кг/с | −2.4071973303563254e−9 |
| Относительная невязка по модулю, % | 3.676814564623544e−7 |

Все проверки этого сохранённого ответа после исправления проходят;
предупреждения PNET остаются. Это повторная обработка данных, не новый запуск
PIPESIM. Оценка массового баланса остаётся NOT_ASSESSED без утверждённого допуска.
Полный цикл base/plus10 и Run/Restart нужно выполнить заново.

Дополнительно исправлено отображение отсутствующих массовых данных:
они больше не объявляются превышением допуска. Причина экспорта передаётся
в MCP и ответ агента, одинаковая ошибка двух MCP-вызовов печатается один раз.
Если одновременно нарушена известная численная проверка, OUT_OF_TOLERANCE
сохраняется: исправление не скрывает такие нарушения.

## Установка

Распакуй `well_agent_mass_balance_fix.zip` в корень локального репозитория
с заменой файлов. Первое обновление массового баланса уже должно быть установлено.
Файл config/mass_balance.json этим исправлением не заменяется.
Новых зависимостей нет. Команды ниже вводятся целиком одной строкой.

После завершения прежних расчётов обнови профиль запуска:

```bat
.venv-mcp\Scripts\python.exe -m src.well_agent_mcp configure-runner --registry "C:\Users\User\Desktop\well-agent-data\mcp_registry" --seed-run-id a6c13b93-011d-5a07-8107-3cfb628eb843 --prepared-model "C:\Users\User\Desktop\well-agent-data\runs\agzu6_isothermal_auto_2\isothermal_auto.pips" --toolkit-root "C:\Program Files\Schlumberger\PIPESIM_PTK_2021.1" --output-root "C:\Users\User\Desktop\well-agent-data\mcp_runs"
```

Ожидается `Runner: CONFIGURED`. Затем выполни новый запрос:

```bat
.venv-mcp\Scripts\python.exe agent.py ask --registry "C:\Users\User\Desktop\well-agent-data\mcp_registry" --run-id a6c13b93-011d-5a07-8107-3cfb628eb843 --allow-run --request "Выполни новый расчёт согласованных base и plus10 для участка АГЗУ-6 и сравни результаты" --output "C:\Users\User\Desktop\well-agent-data\agent_mass_balance_check_02.json"
```

Старый request-id не передавай: после исправления создаётся новый запрос.
При существующем output выбери другое имя файла. Старый неуспешный отчёт
не редактируется и не подменяется новым результатом.
Вторая команда запускает реальный PIPESIM и обращается к RouterAI.

Ожидаются оба сценария с массовыми расходами, конечными невязками и
NOT_ASSESSED из-за незаданного допуска. Пришли вывод и
`agent_mass_balance_check_02.json`. После успешной проверки вернёмся к сценарию
промежуточного видео на 2–3 минуты.

В исправлении пройдены 79 автоматических тестов и повторная обработка
предоставленного реального ответа API. Синтаксис worker и вычислительного
модуля проверен на совместимость с Python 3.8.
