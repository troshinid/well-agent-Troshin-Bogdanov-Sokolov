# Аудит исходных данных

Проверены проектные PDF по АГЗУ, таблица расходов и отчёт МБСНУ.
Аудит выявляет ограничения исходников; инженерное подтверждение
параметров выполняется отдельно.

## Результаты первичной проверки

| Источник | Найдено | Решение |
|---|---|---|
| АГЗУ-1-АГЗУ-2.pdf и АГЗУ-4-1.pdf | Файлы побайтово совпадают; содержат участок АГЗУ-4 → АГЗУ-1 | Не создавать второй участок по названию файла |
| Excel, скважины 114 и 116 | Пропущены дебит жидкости, обводнённость и дебит газа | Сохранить пропуски, не заменять нулями |
| Excel, блок АГЗУ-7 + АГЗУ-60 | Содержит сумму двух групп | Не учитывать повторно как отдельный приток |
| Excel, C36 | Формула пропускает расход воды из F32 | Пересчитать итог в отдельном отчёте, сохранив исходник |

Опись файлов и поиск дублей выполняет scripts/inventory.py.
Проверку Excel выполняет scripts/check_agzu.py.

Результаты сохраняются локально в inventory.csv и agzu_audit.json.
Правила обработки Excel описаны в [словаре данных](data_dictionary.md).

## Неоднозначности

| Источник | Что требует уточнения |
|---|---|
| Excel и Отчет МБСНУ.docx | Различается обводнённость скважин 6014 и 6004; нужно выбрать подтверждённые значения |
| Excel | Не подтверждены единицы расходов и условия учёта газа |
| АГЗУ-7-4.pdf | На титуле указана скважина 6УР, внутри встречается АГЗУ-7; нужно подтвердить соответствие обозначений |
| Проектные PDF | Геометрию и проектные режимы нужно привязать к выбранному участку и сценарию |
| PDF и отчёт МБСНУ | Нужно подтвердить описание флюида и отделить исходные свойства от настроечных вязкостей |
| Отчёт МБСНУ | Для давлений нужно подтвердить единицы, шкалу, происхождение и условия получения |

Проектные расходы не подменяют отсутствующие значения из Excel.
Совпадение названий узлов не подтверждает соединение труб.

## До начала расчётов

Необходимо согласовать:

- участок сети, его входы, выходы, оборудование и упрощения;
- геометрию, свойства флюида и граничные условия;
- участие скважин с неполными данными;
- базовый и дополнительный стационарные сценарии.

По ТЗ преподаватель предоставляет версию ПО и Toolkit-пример,
шаблон модели или проверенный пример сборки, подтверждённые
расчётные данные, ручные эталоны и численные допуски.

Неподтверждённые параметры не заполняются предположениями.
Открытые вопросы уточняются по мере выбора участка.
